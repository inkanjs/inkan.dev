title: "Routes"
description: "Everything a route can say about itself, next to its handler."

```ts
app.get("/teas/:id", {
  params: t.object({ id: t.int() }),
  response: { 200: Tea, 404: t.problem() },
}, ({ params, notFound }) => findTea(params.id) ?? notFound());
```

A route is a method, a path, a spec and a handler. The path takes `:params`, and a `*rest`
at its end; static segments win over params, and params over the rest.

## The spec

| key | what it does |
| --- | --- |
| `params`, `query`, `headers`, `body` | schemas for the input; params, query and headers are text, and are turned into what the schema asks for |
| `response` | status → schema. The first 2xx is the default status, no body means 204; only what the schema lists leaves the server |
| `responseHeaders` | status → header name → schema: headers an answer promises |
| `examples` | `{ name, params, query, headers, body, status, expect, keep, after }`: the docs show them, `inkan check` runs them |
| `security` | `"bearer"`, `"basic"`, `{ apiKey, in }`, a list of them, or `false` |
| `bodyLimit` | the largest body in bytes, instead of the app's |
| `timeout` | milliseconds the handler may take; past them a 504 problem and an aborted `ctx.signal` (**0.7.0**) |
| `cache` | `{ seconds, shared?, max? }`: keeps the handler's answers, see below (**0.7.0**) |
| `use` | middleware for this route only, after the input is checked |
| `summary`, `description`, `tags`, `operationId`, `deprecated` | for the docs |
| `hidden` | keeps the route out of the docs and OpenAPI |

## What a handler returns

| returned | goes out as |
| --- | --- |
| an object or an array | JSON, trimmed to the contract |
| a string | text/plain |
| `` html`…` `` | text/html (**0.7.0**) |
| `reply(status, body, headers?)` | another status or extra headers, typed to the contract |
| `sse(source)` | server-sent events, each one checked against `t.events(...)` |
| a generator of rows, for an array in the contract | JSON written row by row, or NDJSON for `accept: application/x-ndjson` (**0.7.0**) |
| bytes, or a stream of bytes | as they are |
| nothing | 204 |

A list given row by row, such as a generator over a database cursor, never sits in memory
whole: every row is written by the item's writer as it comes, so it holds only what the
contract lists, and in development each one is checked. A row that breaks the contract
there ends the answer early, so no client takes a part for the whole.

## A cache for a route (0.7.0)

```ts
app.get("/stock/:id", { params, cache: { seconds: 600 } }, ({ params, signal }) => stock(params.id, signal));
```

The same params and query within the time get the same answer without the handler, and
requests that come in while it is still being worked out wait for that one answer instead
of each asking the database again. Answers are kept per caller, with the authorization and
cookie headers in the key, unless `shared: true` says they are the same for everybody. A
handler that throws keeps nothing, and at most `max` answers (1000) are kept per route, in
the memory of each process.
