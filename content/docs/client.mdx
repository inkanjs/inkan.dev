---
title: "Typed client"
description: "A client typed from the app itself, without code generation."
---

The contract already knows every path, input and answer, so a client can take its types
from the app itself. No code generation, no OpenAPI step in between:

```ts
// server.ts: define the routes in a chain, so the type of `api` sees them
export const api = inkan()
  .get("/teas/:id", { params: t.object({ id: t.int() }), response: { 200: Tea, 404: t.problem() } }, getTea)
  .post("/teas", { body: NewTea, response: { 201: Tea } }, addTea)
  .mount("/admin", admin);

// web.ts: only the type crosses over, none of the server
import type { api } from "./server.ts";
import { client } from "@vxnsin/inkan/client";

const shop = client<typeof api>("https://shop.example.com", { headers: () => ({ authorization: `Bearer ${token}` }) });

const res = await shop.get("/teas/:id", { params: { id: 1 } });
if (res.ok) res.data.name;               // typed as the contract's Tea, Dates as strings
else if (res.status === 404) res.problem; // every failure is a problem document, never a throw
```

A wrong path, a missing param or a body of the wrong shape does not compile. Check `ok`
first: any status can also come from a proxy on the way, so `status` alone cannot promise
which answer it is. The client is a few lines around `fetch` and runs anywhere fetch does;
pass your own with `{ fetch }`.

Routes written one statement at a time (`app.get(...);`) work as always, but their type
cannot collect them: a type only grows along a chain.

## Events

```ts
for await (const e of shop.events("/exports/:id/events", { params: { id } })) {
  if (e.event === "progress") bar.set(e.data.done / e.data.total); // typed by the event's schema
  if (e.event === "end") break;
}
```

`events(path, { params, query, headers, signal })` reads a route that answers with
[`t.events(...)`](/docs/streams), as an async iterator. Each event is narrowed by its name,
so `e.data` has the type of that event's schema. Leaving the loop, or aborting `signal`,
closes the stream. A stream that does not open throws a `StreamError` with its `status`
and its `problem`. Only routes with an events contract are offered as paths. New in 0.7.0;
[jobs](/docs/jobs) use it to follow their progress.

## WebSockets

```ts
const room = shop.ws("/rooms/:room", { params: { room: "tea" }, query: { name: "ana" } });
await room.ready;
room.send({ type: "say", text: "hello" });           // typed by the route's message
for await (const m of room) if (m.type === "said") show(m.text); // typed by its send
```

`ws(path, { params, query, headers })` opens a route made with [`app.ws`](/docs/websocket)
with the platform's `WebSocket`. Leaving a `for await` loop closes it; `headers` go with the
upgrade only in Node. New in 0.7.0.

## Routes out of plugins

Routes a plugin defines in its chain and returns with its scope reach the client after
`register`, under their prefix: see
[Writing a plugin](/docs/plugins#routes-out-of-plugins-in-the-typed-client). New in 0.7.0.
